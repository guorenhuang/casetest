# Q3 系统设计 — Prompt 救火（分镜生成 Agent）

## 1. 问题域

线上「短剧分镜生成」**system prompt** 导致：

- 输出过长 → 下游 token/解析被打爆  
- 非合法 JSON → 解析失败  
- 风格漂移 → 同一剧情输出不一致  
- 擅自改剧情 → 用户核心设定丢失  

试卷声明：**至少 4 个隐藏问题**；工作方式是**先证据、后修复**，杜绝凭感觉一改了之。

## 2. 诊断工作流（硬性流程对齐）

```
┌────────────┐     ┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│ Run ≥5     │ ──▶ │ issues.md   │ ──▶ │ Fix prompt   │ ──▶ │ before/after │
│ 真实推理   │     │ 现象+证据   │     │ 映射表       │     │ ≥2 组对比    │
└────────────┘     └─────────────┘     └──────────────┘     └─────────────┘
```

- **观测**：≥5 条不同长度、不同题材（甜宠/悬疑/复仇/穿越/家庭伦理等）剧情，**原样贴输出**到 `observations.md`。
- **问题清单**：每条问题 = 现象 + 证据片段 + 为何是问题；**至少 4 条**（与「隐藏问题」一致）。
- **与 AI 协同**：须防敷衍（「prompt 挺好」）；transcript 中体现**逼迫模型逐条给证据**的策略。
- **修复**：`fixed_prompt.md` = 新 prompt + **每一处改动 ↔ 解决的 issue ID** 的映射表；禁止「一锅端」式笼统说明。
- **验证**：`before_after.md` ≥2 组对比，证明修复对 JSON/长度/风格/忠实度等有效。

## 3. 待诊断 Prompt（试卷规定原样）

```
你是一个资深的短剧分镜师，请根据用户给的剧情，生成详细的分镜表。
请尽可能详细，越详细越好，把你能想到的都写出来。
输出 JSON 格式，字段你自己设计。
注意要符合年轻人喜欢的风格，有爆点。
如果剧情不合适，就自己改一下让它更适合短剧。
剧情：{plot}
```

## 4. 典型根因类别（诊断时可作检查单，非标准答案）

> 下列仅作分类参考，考生须在 `issues.md` 用自己跑出的**证据**落地。

- **无 schema / 无字段约束** → JSON 结构不稳定  
- **「尽可能详细」无上限** → 输出过长  
- **「年轻人喜欢」主观** → 风格漂移  
- **允许改剧情** → 设定被篡改  
- **无解析/转义/节选说明** → 字符串内引号等破坏 JSON
