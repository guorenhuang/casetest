# Q2 需求规则 — 评论审核 Agent（25 分 · 建议 60 分钟）

## 业务需求（来自一句话）

自动审核评论：**通过** / **疑似进人工** / **明确违规屏蔽**；应对广告、引流、骂人、加微信、拼音/emoji 绕词、大规模日更。

## 能力覆盖（每条须可演示）

| 能力 | 说明 |
|------|------|
| 敏感词词库 | 可配置词表 |
| 正则规则 | 模式命中 |
| 拼音/谐音绕开 | 如加 wei xin、jia v、纯首字母等 |
| 连续数字 | QQ/手机/微信号类格式 |
| 图片 OCR | 给定图床 URL；真实 API 或 mock，须标明接入点 |

## 硬性要求

| # | 规则 |
|---|------|
| R1 | **规则不外置在业务代码**：yaml/json/DB 任选；**新规则不改业务代码、不重发版**（以进程/加载策略实现） |
| R2 | **AI 可降级**：模型超时/不可用时，规则部分独立跑通并返回结果 |
| R3 | **命中证据**：每条输出须说明「为何是该判断」— 规则 ID/细节或模型 reason |
| R4 | **数据集**：≥30 条评论；≥5 条**故意刁钻**；你 review 后说明取舍 |
| R5 | **报告**：跑完 30 条 → `run_report.md`：每条结论 + 命中 + 是否合理 |

## 交付物

- `src/`、`rules.yaml` 或 `rules.json`、`dataset.json`、`run_report.md`、`README.md`、`transcript.md`

## 非功能

- README 含架构、部署、加规则、换模型说明。
- Transcript 展示从一句话需求到可运行 Skill 的过程。
